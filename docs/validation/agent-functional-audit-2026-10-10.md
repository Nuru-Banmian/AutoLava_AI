# AutoLava-AI Agent 问题原因、修复方法与验证

> 版本边界：本文保存多轮修复证据。315 项 Agent/Memory 通过属于图型名识别及月份追问修复之前的源码；后续 50 项、30 项、20 项是不同范围的局部复测，不能相加或冒充最新源码全范围通过。2026-10-10 的发布整合另见 `issue-279-agent-release-2026-10-10.md`。本文真实模型证据未在整合远端源码后全部重跑。

日期：2026-10-10（Asia/Shanghai）。所有真实模型验证均使用当前配置的模型、迁移后的临时 SQLite 和虚构门店数据；不代表生产环境或真实门店的运行结果。

## 1. 模型参数格式错误，以及校验器崩溃

### 现象与原因

历史日期问答中，真实模型将 `targets` 发送成包含 JSON 文本的字符串，而工具合同要求对象数组。模型看见数组 schema 也不意味着每次调用都符合 schema。旧临时校验器直接遍历 `targets` 并对元素调用 `.get()`；遍历字符串得到字符，因而触发 `AttributeError`，阻断了失败记录。

此外，旧版折线图续页曾携带 `catalog_version`，与续页合同冲突。经过纠错仍有真实模型参数失败。用户最终要求删除 Agent 查询翻页，因此最终实现已经移除续页合同，旧续页修复与失败日志仅保留为问题原因证据。

### 修复

- 保留严格服务端校验，不将字符串自动转换成数组，不将无效调用当成业务查询成功。
- 模型 schema 明确 `targets` 为对象数组；最终只接受带 `catalog_version/targets` 的新查询，拒绝旧 `continuations`。移除续页参数、游标签名/校验、自动翻页循环，以及旧图快照读取实现；旧图查看接口继续按门店、账户、消息关联校验。
- 对 `targets` 的 `list_type` 错误给出中文纠错说明及对象数组示例，要求模型重新构造调用。只暴露错误类型和结构，不回显用户完整输入或凭证。
- 不连续历史日期的状态/金额问答优先分为独立单日目标，分别核对匹配记录，明确区分休息、未统计和未录入。
- 临时校验器先检查参数容器及目标元素形状，将错误记录为 `parameter_shape:store_query.targets` 或其他对应失败；即使模型随后重试成功，原参数失败仍保留。工具的 `invalid_tool_arguments` 也记录为失败。

### 验证边界

`validator-shape-red.txt` 保留校验器崩溃；`validator-shape-fixed.txt` 显示相同旧证据被明确判为失败。`targets-feedback-red.txt`、`format-contracts-green.txt` 记录纠错反馈及 schema 回归；`continuation-feedback-red.txt`、`continuation-feedback-green-final.txt` 记录续页专属反馈回归。

真实模型仍可能输出不合法参数。修复保证错误被拒绝、可纠错、有失败证据，并在无法取得必要业务证据时失败退出；不保证供应商模型每次参数生成都正确。历史日期的成功重测与失败尝试必须分别报告。

## 2. 未读完明细却声称全部读取

### 现象与原因

完整查询快照有 31 行，模型只取得前 29 行，但回答曾宣称全部 31 行明细已读完。图表可以直接投影完整快照，因此图有 31 个点不等于模型读完 31 行。原运行时已附加真实的部分完成提示，却先将模型错误声明流式发布，造成前后矛盾。

### 修复

- 继续以工具最新 `read_ranges`、`unread_ranges` 和行数核对读取进度。
- 仍有未读行或查询失败时，暂缓发布回答文字，在发布前检查明显的全部读取声明。
- 发现矛盾时给模型一次有界纠错机会，附带真实读取进度；持续矛盾则失败，不把错误文字写入 HTTP/SSE 的最终回答。
- 图的完整点数与模型已读行数分别说明；完整汇总仍依据工具的全部匹配口径，不能把汇总误说成只覆盖已读页。

`unread-claim-red.txt` 保留原症状；`fresh-guards-final.txt` 包含该回归的绿色结果。检查覆盖已识别的明确完成措辞，不代表能自动识别模型任意改写的所有错误声明。

## 3. 图表追问重新查询最新数据

最新要求取代历史快照问答：旧图继续在聊天中查看，Agent 回答图表追问时重新查询，沿用近期日期、指标、分组；必要信息不足先追问，需要时生成新图，明确说明最新数据。

实现关闭模型可见的 `saved_chart` 路由和 `read_saved` 操作；兼容收到的旧路由被转为查询，旧快照不能满足本轮证据要求。历史图的助手文字不再作为数值/分析重新注入，只保留日期范围、标题、单位和图型线索。完整历史仍持久化，短期输入最多最近 10 条消息。

真实对照先生成首日 180 的图，再把临时台账首日改为 999。追问必须查询得到 999 和次日 181，新图首日为 999，原图完整 payload 保持不变。旧 `read_saved` 测试通过不再作为新方案通过证据。

## 4. 双月比较图只有一个月份

`block=main` 只包含本期行，`block=comparison` 只包含基期行，均不会合并。旧调用以 7 月为主区间、6 月为 compare，却只投影 main，得到一个点，文字仍声称双月比较。

充值恢复后的真实复测仍复现该错误（`recharged-priority-fixed`），证明仅靠 schema 和技能指导不足。新增发布前检查：已识别双月对比意图且 compare 的两个月未全部出现在选定 block 时，返回 `chart_periods_missing`，不保存错误图，要求重新查询覆盖两个月的数据。修复保留默认 block 语义，schema 和技能明确两侧不合并。双月图使用覆盖 6–7 月的独立查询及 `group_by:["month"]`；需要差额/变化率时另用后端 compare。真实保存的双月图核对 6 月 4449、7 月 5265；后端差额 816、变化率 18.34%。

分类堆叠图还曾用“台账合计、公司结算”两个系列冒充“现金、刷卡、公司结算”。对已识别分类堆叠意图增加 `chart_categories_missing` 拒绝；技能明确查询 `income_composition`、`amount`，按 `month/category` 分组，以 category 堆叠。真实保存数据为：6 月现金 3099、刷卡 1350、结算 200；7 月 3915、1350、300；8 月 4927、1400、400。

两项严格回归在修复前失败（`recharged-chart-intent-final-red.txt`），修复后相关 30 项通过（`recharged-chart-guards-green.txt`）。最初临时测试构造遗漏 operation 或不满足原堆叠合同的失败属于测试构造错误，另存日志；不能冒充上述有效红色回归。

## 5. 上下文预算与隐藏思考

当前默认上下文预算为 48,000 字符，可配置范围 8,000–64,000。8,000 是低配置回归测试，不是日常默认。模型供应商 token 上限与应用的序列化字符预算不同；提高应用预算不能修复参数类型错误或错误完成声明。

提示词扩展曾令 6000 字的完整用户消息在 8000 字预算下失败。通过删减重复指导修复，保留原测试上限和完整用户消息；`history-current-red-details.txt`、`history-current-green.txt` 保留红绿证据。本次按用户确认维持 48,000 默认，不修改真实 `.env`。

隐藏思考默认关闭，保留开关。既有真实小样本对照发现开启时耗时及超时风险更高；关闭也有语义失败，不承诺准确性完全不受影响，也没有大样本准确率结论。

## 6. 查询策略与删除 Agent 翻页

采用“简短 Prompt 原则 + 按需 Skill 方法 + 后端关键检查”：

| 用户请求 | 查询方式 |
| --- | --- |
| 一般月收入 | 一次覆盖整月的指标汇总，当前月截至当地今天 |
| 一般年收入 | 一次覆盖全年的指标汇总，当前年先给截至今天的总结 |
| 周数据 | 一次查询一周，按天分组；无需每天分别调用 |
| 后续细问 | 按用户要求拆成月、日或分类，重新读取当前数据 |
| 明确比较、分类、图表或明细 | 按指定粒度查询，比较差额/变化率仍使用后端 compare |
| 长明细超过单次容量 | 如实说明部分完成，提示缩小日期范围；不声称已读完 |

总原则写入助手 Prompt 和查询阶段系统指导；具体数据域、指标、分组、日期、结算口径放入 `store-analysis/SKILL.md`。后端从本轮用户问题识别一般月/年收入请求，对默认细分行、筛选/排名或非完整期间请求返回 `query_granularity_required`，要求模型修正；明确细分请求可使用原有字段和分组能力。该检查覆盖已识别的表达，不代表理解任意自然语言的所有情况。

Agent 查询工具删除 `continuations`、`page_size`、`next_cursor` 与自动翻页循环。`row_limit` 仅为**一次返回的完整行上限**（默认/最多 200），仍受单次 12,000 字符、上下文及快照容量限制；没有下一页。未返回明细保留真实覆盖说明，用户后续使用更小日期范围进行新查询。后端全匹配汇总与完整图表快照继续保留，图表点数与模型已读明细分别说明。会话历史查看和系统其他列表分页不在此次删除范围。

月份结算按开票月份计整笔确认收入，不能分摊到每天后再重复求和。周台账按天展示时不混入日结算额。

策略真实模型验证发生在删除翻页之前：7 月总收入 5565；年度截至门店当地日期总收入 23065；追问后才按月拆分，其中 7 月仍为 5565；一周七日台账合计 1128，未统计日为空。参数、后端指标、回答数值与 HTTP/SSE 均核对，证据为 `summary-strategy-live/summary-strategy.json` 与检查文件。删除后首次真实复测被供应商 403 拒绝。用户充值后再次验证当前配置返回 HTTP 200；最终修复源码的月、年、细问、周四项复测均通过，数值仍为 5565、23065、5565、1128（`recharged-final-summary`）。

旧“逐页读完”测试随删除退役，改为验证：60 行含完整长事件只执行一次查询、返回真实部分完成、没有游标；缩小范围后使用新引用，读到更新后的 999；旧续页参数被明确拒绝；图表仍保留完整快照点数。测试数量变化是功能合同变更，旧红色日志保留。

### 失败与边界

- 原真实模型出现 `targets` 字符串和非法续页参数；即使重试后回答 completed，首次参数错误仍判失败，见 `final-acceptance.json` 的失败记录。续页功能已按用户要求删除，不再继续修复。

- 删除后的局部测试最初 2 失败、101 通过（`no-pagination-focused.txt`）：两项多轮受控模型测试的第二轮查询助手函数缺少目录回执，抛出内部错误。已补齐测试模型第二轮目录动作，仍保留新数据、数值、范围和不翻页断言，未自动转换参数或放松检查。
